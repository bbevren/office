================================================================================
                           1. SYSTEM OVERVIEW
================================================================================

This project provides a fully client-side OnlyOffice document editor that runs
in the browser without requiring a traditional OnlyOffice Document Server.

KEY FEATURES:
- Create new Word, Excel, and PowerPoint documents
- Open existing documents in many formats (see Section 10)
- Edit documents with full OnlyOffice functionality
- Export to PDF (Word, Excel, PowerPoint)
- Download/export documents in Office formats
- Handle embedded images
- No server-side document processing required (except for format conversion)
- Optional co-editing support (disabled by default)

HOW IT'S POSSIBLE:
OnlyOffice has a "CryptPad-patched" version that was designed to work with
CryptPad's encrypted collaborative editing. This version includes:
- A "connectMockServer" API that replaces the WebSocket connection
- Client-side document loading via blob URLs
- Internal binary format (DOCY/XLSY/PPTY) for documents
- APP hooks for parent window communication

We leverage these features to create a standalone editor.

================================================================================
                         2. ARCHITECTURE & STACK
================================================================================

FRONTEND:
---------
- Pure HTML/CSS/JavaScript (no framework)
- OnlyOffice Web Apps v8.3 (CryptPad-patched version)
- DocsAPI.DocEditor for editor initialization

BACKEND:
--------
- Node.js HTTP server (no Express, minimal dependencies)
- x2t-wasm: WebAssembly build of OnlyOffice's x2t converter
- Static file serving for OnlyOffice assets

KEY TECHNOLOGIES:
-----------------
1. OnlyOffice Web Apps (CryptPad patch)
   - Located in: public/onlyoffice/v8/
   - Provides the editor UI and document editing logic
   - Modified to work without Document Server

2. x2t-wasm Converter
   - Files: x2t.js, x2t.wasm
   - Converts between Office formats (DOCX, XLSX, PPTX) and internal format
   - Runs in Node.js (could also run in browser with modifications)

3. Mock Server Pattern
   - Replaces WebSocket communication with in-memory callbacks
   - Handles document loading, saving, locking, and collaboration messages

DOCUMENT FORMAT:
----------------
OnlyOffice internally uses a custom binary format:
- DOCY (Word documents): "DOCY;v5;{size};{base64data}"
- XLSY (Excel spreadsheets): "XLSY;v2;{size};{base64data}"
- PPTY (PowerPoint presentations): "PPTY;v1;{size};{base64data}"

These are text strings containing a header and base64-encoded binary data.

================================================================================
                      4. HOW IT WORKS - DETAILED FLOW
================================================================================

A. CREATING A NEW DOCUMENT (Manual)
-----------------------------------

1. User clicks "New Word/Excel/PowerPoint" button

2. Client loads the appropriate template:
   - Fetches /templates/oodoc_base.js (or oocell/ooslide)
   - Template returns a string: "DOCY;v5;229432;{base64data}..."
   - This is an empty document in OnlyOffice internal format

3. Client creates a Blob URL from the template string:
   ```javascript
   const blob = new Blob([templateString], { type: 'text/plain' });
   const url = URL.createObjectURL(blob);
   ```

4. Client initializes DocsAPI.DocEditor with config:
   ```javascript
   const config = {
       documentType: 'word',  // or 'spreadsheet' or 'presentation'
       document: {
           fileType: 'docx',
           url: blobUrl,      // The blob URL with template
           title: 'Untitled.docx'
       },
       editorConfig: { mode: 'edit' }
   };
   editor = new DocsAPI.DocEditor('editor', config);
   ```

5. Client connects the Mock Server:
   ```javascript
   editor.connectMockServer(mockServerObject);
   ```

6. OnlyOffice loads the document from the blob URL and initializes

B. CREATING A NEW DOCUMENT (URL Parameter)
------------------------------------------

Users can create a new document by navigating to a URL with filename:

URL FORMAT:
  http://localhost:8080/?f=MyDocument.docx
  http://localhost:8080/?f=Budget.xlsx
  http://localhost:8080/?f=Presentation.pptx

HOW IT WORKS:

1. On page load, JavaScript checks for 'f' URL parameter:
   ```javascript
   const urlParams = new URLSearchParams(window.location.search);
   const fileParam = urlParams.get('f');
   ```

2. If 'f' parameter exists, extract filename and extension:
   ```javascript
   const filename = fileParam.replace(/\.[^/.]+$/, '');  // Remove extension
   const ext = fileParam.split('.').pop().toLowerCase();
   ```

3. Map extension to document type:
   ```javascript
   const typeMap = {
       'docx': 'word', 'doc': 'word', 'odt': 'word', 'rtf': 'word',
       'xlsx': 'cell', 'xls': 'cell', 'ods': 'cell', 'csv': 'cell',
       'pptx': 'slide', 'ppt': 'slide', 'odp': 'slide'
   };
   const docType = typeMap[ext];
   ```

4. Set filename in input field and create new document:
   ```javascript
   document.getElementById('filename').value = filename;
   createDocument(docType);  // Creates empty document of that type
   ```

SUPPORTED EXTENSIONS FOR NEW DOCUMENTS:
- Word: docx, doc, odt, rtf (creates Word editor)
- Excel: xlsx, xls, ods, csv (creates Excel editor)
- PowerPoint: pptx, ppt, odp (creates PowerPoint editor)

EXAMPLE URLS:
- /?f=Report.docx        → Opens Word editor, filename "Report"
- /?f=Q4-Budget.xlsx     → Opens Excel editor, filename "Q4-Budget"
- /?f=Sales-Pitch.pptx   → Opens PowerPoint editor, filename "Sales-Pitch"
- /?f=Notes.doc          → Opens Word editor, filename "Notes"
- /?f=Data.csv           → Opens Excel editor, filename "Data"

COMBINING WITH CO-EDIT:
- /?f=Document.docx&coedit=true  → New Word doc with co-editing enabled

C. OPENING AN EXISTING FILE
---------------------------

1. User selects a file via the file picker

2. Client reads the file as ArrayBuffer:
   ```javascript
   const arrayBuffer = await file.arrayBuffer();
   ```

3. Client sends to server for conversion:
   ```javascript
   fetch('/api/open', {
       method: 'POST',
       headers: { 'X-File-Extension': 'docx' },
       body: arrayBuffer
   });
   ```

4. Server converts using x2t-wasm:
   - Writes input file to virtual filesystem
   - Runs x2t conversion to internal format (.bin)
   - x2t outputs: "DOCY;v5;{size};{base64data}"
   - Extracts any embedded images to data URLs

5. Server returns JSON:
   ```json
   {
       "success": true,
       "data": "DOCY;v5;50544;...",
       "images": {
           "image1.jpg": "data:image/jpeg;base64,..."
       }
   }
   ```

6. Client creates blob URL and initializes editor (same as new document)

7. Mock Server's getImageURL() returns data URLs for embedded images

C. DOWNLOADING/SAVING A DOCUMENT
--------------------------------

1. User clicks Download or uses File > Save

2. OnlyOffice sends POST to /onlyoffice/v8/downloadas/{docId}
   - Body contains the document in internal binary format
   - Query params specify output format (e.g., outputformat=65 for DOCX)

3. Server receives the binary and converts using x2t-wasm:
   - Input: Internal binary format
   - Output: DOCX/XLSX/PPTX file

4. Server stores the converted file and returns download URL

5. Client triggers file download

================================================================================
                      5. MOCK SERVER IMPLEMENTATION
================================================================================

The Mock Server is the key component that makes OnlyOffice work without a
real Document Server. It's implemented in public/index.html.

MOCK SERVER OBJECT STRUCTURE:
-----------------------------

```javascript
const mockServer = {
    // Called when OnlyOffice sends a message
    onMessage: function(msg) {
        switch(msg.type) {
            case 'saveChanges':
                // Handle document changes (for collaborative editing)
                // Acknowledge: send { type: 'saveChanges', changesIndex, locks }
                break;
            
            case 'getLock':
                // Handle editing lock requests
                // Grant lock: send { type: 'getLock', locks: {...} }
                break;
            
            case 'isSaveLock':
                // Check if save is locked
                // Response: send { type: 'saveLock', saveLock: false }
                break;
            
            case 'unSaveLock':
                // Release save lock
                break;
            
            case 'cursor':
                // Cursor position updates (ignore in single-user)
                break;
            
            case 'openDocument':
                // Handle image URL requests (e.g., when duplicating slides)
                break;
        }
    },
    
    // Return list of participants
    getParticipants: function() {
        return {
            list: [{ id: 'user_local', username: 'Guest', view: false }],
            index: 0
        };
    },
    
    // Called after authentication completes
    onAuth: function() {
        console.log('Editor authenticated');
    },
    
    // Get image URL by name - CRITICAL for image loading
    getImageURL: function(name) {
        // Return Promise that resolves to image URL
        if (currentDocumentImages[name]) {
            return Promise.resolve(currentDocumentImages[name]);
        }
        return Promise.resolve('');
    },
    
    // Return initial collaborative changes (empty for single-user)
    getInitialChanges: function() {
        return [];  // No pending changes
    },
    
    // Called when document binary is ready
    onDocumentBinaryReady: function(binary) {
        // Store for export
    }
};

// Connect to editor
const sendToEditor = editor.connectMockServer(mockServer);
```

SENDING MESSAGES TO EDITOR:
---------------------------

The connectMockServer() returns a function to send messages back:

```javascript
// Grant a lock
sendToEditor({
    type: 'getLock',
    locks: { 'block_id': { user: 'user_local', block: blockData } }
});

// Acknowledge save
sendToEditor({
    type: 'saveChanges',
    changesIndex: 5,
    locks: []
});
```

================================================================================
                   6. CO-EDITING & LOCK MECHANISM
================================================================================

The CryptPad-patched OnlyOffice includes collaborative editing features.
By default, we DISABLE co-editing to avoid lock visualization issues.

UNDERSTANDING THE LOCK MECHANISM:
---------------------------------

When multiple users edit a document, OnlyOffice uses locks to prevent
conflicts. The editor:
1. Requests locks via 'getLock' message when user starts editing a paragraph
2. Shows visual indicators (colored bars) for locked regions
3. Releases locks via 'releaseLock' when editing completes

LOCK VISUALIZATION PROBLEM:
---------------------------

In single-user mode, if locks are not handled correctly, OnlyOffice shows
red "Guest" labels and locks controls after typing. This happens because:
1. The editor requests locks via mock server
2. If lock response isn't formatted correctly, the lock is marked as "Other"
3. Locks owned by "Other" users show red indicators and may freeze controls

THE SOLUTION - TWO MOCK SERVER MODES:
-------------------------------------

1. connectMockServer (Full mode) - Used when ?coedit=true in URL:
   - Handles all collaborative messages
   - Returns empty locks (allows editing but may show indicators)
   
2. connectMockServerFast (Single-user mode) - Default:
   - Returns locks as "owned by current user" (locktype_Mine)
   - Combined with fast mode, prevents lock visualization
   - Minimal collaborative overhead

KEY LOCK HANDLING CODE (connectMockServerFast):
-----------------------------------------------

```javascript
// When editor requests a lock, claim it for this user
if (msg.type === 'getLock') {
    const blocks = msg.block || [];
    const locks = {};
    blocks.forEach(block => {
        locks[JSON.stringify(block)] = {
            block: block,
            user: myOOId,        // Same as current user ID
            time: Date.now(),
            sessionId: myOOId
        };
    });
    sendMsg({ type: 'getLock', locks: locks });
    return;
}
```

WHY THIS WORKS:
---------------

In sdk-all.js, the DrawLockParagraph function has this condition:

```javascript
if (lock_type === locktype_None || 
    IsLockObjectsEnable === false || 
    isViewMode || 
    lock_type === locktype_Mine && CollaborativeEditing.Is_Fast())
    return;  // Don't draw lock indicator
```

Our solution ensures:
1. lock_type = locktype_Mine (user owns the lock)
2. CollaborativeEditing.Is_Fast() = true (fast mode enabled via APP.onFastChange)

ADDITIONAL LOCK PATCHES (disableLockMechanism):
-----------------------------------------------

The public/index.html includes a disableLockMechanism() function that
patches the iframe's OnlyOffice instance for extra safety:

- Sets IsLockObjectsEnable = false
- Patches DrawLockParagraph to do nothing
- Forces Is_Fast() to return true
- Patches IsSelectionLocked to return false
- Makes Add_CheckLock a no-op

ENABLING CO-EDITING FOR FUTURE USE:
-----------------------------------

To enable full co-editing (for a custom collaboration server):
1. Add ?coedit=true to the URL
2. The full connectMockServer will be used
3. Replace mock server with your WebSocket implementation
4. Route messages through your collaboration server

================================================================================
                     7. PDF CONVERSION & EXPORT
================================================================================

PDF export uses OnlyOffice's internal PDF rendering with x2t-wasm conversion.

HOW PDF EXPORT WORKS:
---------------------

1. User clicks "Download as PDF" button

2. OnlyOffice renders document to internal PDF format (pdf.bin):
   - Calls window.parent.APP.printPdf(dataContainer, callback)
   - dataContainer.data contains the pdf.bin binary data

3. Our APP.printPdf implementation:
   a. Extracts pdf.bin from dataContainer
   b. Gets document binary (docBin) for additional data
   c. Sends both to server: POST /api/print-pdf

4. Server converts pdf.bin to actual PDF:
   - Uses x2t-wasm to convert pdf.bin to PDF
   - Returns the rendered PDF file

5. Client downloads the PDF file

PDF EXPORT CODE (APP.printPdf):
-------------------------------

```javascript
window.APP.printPdf = function(dataContainer, callback) {
    const pdfBinData = dataContainer?.data;
    if (!pdfBinData) {
        callback && callback({ status: 'err' });
        return;
    }
    
    // Get document binary for full conversion
    let docBin = window.currentDocumentBinary;
    if (!docBin) {
        // Try to get from editor API
        const iframe = document.querySelector('#editor iframe');
        const api = iframe?.contentWindow?.Asc?.editor;
        if (api?.asc_nativeGetFile) {
            docBin = api.asc_nativeGetFile();
        }
    }
    
    const formData = new FormData();
    if (docBin) formData.append('docbin', new Blob([docBin]), 'document.bin');
    formData.append('pdfbin', new Blob([pdfBinData]), 'pdf.bin');
    formData.append('filename', filename);
    
    fetch('/api/print-pdf', { method: 'POST', body: formData })
        .then(response => response.blob())
        .then(pdfBlob => {
            // Download PDF
            const url = URL.createObjectURL(pdfBlob);
            const a = document.createElement('a');
            a.href = url;
            a.download = filename + '.pdf';
            a.click();
            callback({ status: 'ok' });
        })
        .catch(err => callback({ status: 'err' }));
};
```

SERVER-SIDE PDF CONVERSION (/api/print-pdf):
--------------------------------------------

```javascript
// In server.js
async function handlePrintPdf(req, res) {
    // 1. Extract pdf.bin and document.bin from multipart form
    // 2. Write to x2t virtual filesystem
    // 3. Create conversion params with outputformat: 513 (PDF)
    // 4. Run x2t conversion
    // 5. Read output PDF and return to client
}
```

================================================================================
                     8. DOCUMENT CONVERSION (x2t-wasm)
================================================================================

x2t is OnlyOffice's document converter. The WASM version runs in Node.js.

CONVERSION PARAMETERS (XML):
----------------------------

```xml
<?xml version="1.0" encoding="utf-8"?>
<TaskQueueDataConvert>
  <m_sFontDir>/working/fonts/</m_sFontDir>
  <m_sThemeDir>/working/themes</m_sThemeDir>
  <m_sFileFrom>/working/input.docx</m_sFileFrom>
  <m_sFileTo>/working/output.bin</m_sFileTo>
  <m_bIsNoBase64>false</m_bIsNoBase64>
</TaskQueueDataConvert>
```

KEY PARAMETERS:
- m_sFileFrom: Input file path (in virtual filesystem)
- m_sFileTo: Output file path
- m_bIsNoBase64: false = output as base64 string (DOCY format)
                 true = output as raw binary

CONVERSION CODE:
----------------

```javascript
// Initialize virtual filesystem
x2t.FS.mkdir('/working');
x2t.FS.mkdir('/working/media');

// Write input file
x2t.FS.writeFile('/working/input.docx', inputBuffer);

// Write conversion params
x2t.FS.writeFile('/working/params.xml', paramsXml);

// Run conversion
const result = x2t.ccall("main1", "number", ["string"], ["/working/params.xml"]);

// Read output (as UTF-8 text for DOCY format)
const outputBytes = x2t.FS.readFile('/working/output.bin');
const outputString = new TextDecoder('utf-8').decode(outputBytes);
// outputString = "DOCY;v5;50544;base64data..."

// Read extracted images
const mediaFiles = x2t.FS.readdir('/working/media');
for (const file of mediaFiles) {
    const imageData = x2t.FS.readFile('/working/media/' + file);
    // Convert to data URL
}
```

FORMAT CODES (outputformat parameter):
--------------------------------------
- 65: DOCX (Word)
- 257: XLSX (Excel)  
- 129: PPTX (PowerPoint)
- 513: PDF

================================================================================
                         9. IMAGE HANDLING
================================================================================

Images are handled in three scenarios:

A. IMAGES IN OPENED DOCUMENTS
-----------------------------

1. When x2t converts DOCX to DOCY, images are extracted to /working/media/
2. Server reads these and converts to base64 data URLs
3. Server returns images in response: { images: { "image1.jpg": "data:..." } }
4. Client stores in currentDocumentImages object
5. Mock Server's getImageURL() returns these data URLs when OnlyOffice requests

B. INSERTING NEW IMAGES (From File)
-----------------------------------

1. OnlyOffice calls window.parent.APP.AddImage(successCallback, errorCallback)
2. Our implementation opens a file picker
3. User selects image file
4. We read file as data URL using FileReader
5. We call successCallback({ name: 'image_123.jpg', url: 'data:...' })
6. OnlyOffice inserts the image using the provided URL

```javascript
window.APP.AddImage = function(successCallback, errorCallback) {
    const input = document.createElement('input');
    input.type = 'file';
    input.accept = 'image/*';
    
    input.onchange = function(e) {
        const file = e.target.files[0];
        const reader = new FileReader();
        
        reader.onload = function(evt) {
            const dataUrl = evt.target.result;
            const imageName = 'image_' + Date.now() + '.jpg';
            
            // Store in cache
            currentDocumentImages[imageName] = dataUrl;
            
            // Add to OnlyOffice document URLs
            const iframe = document.querySelector('#editor iframe');
            const documentUrls = iframe.contentWindow.AscCommon.g_oDocumentUrls;
            documentUrls.addImageUrl(imageName, dataUrl);
            
            // Call success callback
            successCallback({ name: imageName, url: dataUrl });
        };
        
        reader.readAsDataURL(file);
    };
    
    input.click();
};
```

C. INSERTING IMAGES FROM URL
----------------------------

1. OnlyOffice calls window.parent.APP.AddImageUrl(url, successCb, errorCb)
2. We try to load image client-side (may fail due to CORS)
3. If CORS fails, we proxy through server: GET /api/fetch-image?url=...
4. Server fetches image and returns as data URL
5. We call successCallback with the data URL

================================================================================
              11. CRYPTPAD-PATCHED ONLYOFFICE (APP HOOKS)
================================================================================

The CryptPad-patched OnlyOffice communicates with the parent window via
window.parent.APP hooks. These must be implemented for the editor to work.

REQUIRED APP HOOKS:
-------------------

1. APP.getImageURL(name, callback)
   Called when editor needs an image URL.
   Return: Promise resolving to the image URL (data: or http:)

2. APP.UploadImageFiles(files, type, id, jwt, callback)
   Called when user pastes or drags images into editor.
   Process the files and call callback when done.

3. APP.AddImage(successCallback, errorCallback)
   Called when user clicks "Insert Image" button.
   Open file picker and return selected image via successCallback.

4. APP.AddImageUrl(url, successCallback, errorCallback)
   Called when user inserts image from URL.
   Load the image and return via successCallback.

5. APP.printPdf(dataContainer, callback)
   Called when user exports to PDF.
   dataContainer.data contains pdf.bin binary data.
   Send to server for conversion and trigger download.

6. APP.changeTheme(indexTheme)
   Called when user changes presentation design theme.
   Used for collaborative theme syncing (we just log and allow).

7. APP.onFastChange(isFast)
   Called when editor switches between fast/strict collaborative mode.
   We always force fast mode to prevent lock visualization.

================================================================================
                  12. INTEGRATING WITH YOUR FILE SYSTEM
================================================================================

To integrate this editor with your own file storage system:

A. LOADING DOCUMENTS FROM YOUR STORAGE
--------------------------------------

Replace the file picker logic in openFile():

```javascript
async function loadDocumentFromYourStorage(documentId) {
    // 1. Fetch document from your storage
    const response = await fetch('/your-api/documents/' + documentId);
    const arrayBuffer = await response.arrayBuffer();
    const fileExtension = 'docx';  // Get from your metadata
    
    // 2. Convert to OnlyOffice format
    const convertResponse = await fetch('/api/open', {
        method: 'POST',
        headers: { 'X-File-Extension': fileExtension },
        body: arrayBuffer
    });
    const result = await convertResponse.json();
    
    // 3. Store images
    currentDocumentImages = result.images || {};
    
    // 4. Create blob URL
    const blob = new Blob([result.data], { type: 'text/plain' });
    const url = URL.createObjectURL(blob);
    
    // 5. Initialize editor
    createEditorForOpenedFile(docType, filename, fileExtension, url);
}
```

B. SAVING DOCUMENTS TO YOUR STORAGE
-----------------------------------

Intercept the download process:

```javascript
// In the download handler, instead of triggering browser download:
async function saveToYourStorage(documentId, fileBuffer, filename) {
    await fetch('/your-api/documents/' + documentId, {
        method: 'PUT',
        headers: { 'Content-Type': 'application/octet-stream' },
        body: fileBuffer
    });
}
```

C. AUTO-SAVE IMPLEMENTATION
---------------------------

OnlyOffice can send periodic changes. Capture them:

```javascript
// In mockServer.onMessage:
case 'saveChanges':
    // Store changes for auto-save
    documentChanges.push(...msg.changes);
    
    // Debounce auto-save
    clearTimeout(autoSaveTimer);
    autoSaveTimer = setTimeout(() => {
        saveChangesToYourStorage(documentChanges);
    }, 5000);
    
    // Acknowledge
    sendToEditor({ type: 'saveChanges', changesIndex: documentChanges.length });
    break;
```

D. COLLABORATIVE EDITING (Advanced)
-----------------------------------

For real-time collaboration, you'd need to:

1. Replace mock server with WebSocket connection to your server
2. Broadcast changes to all connected clients
3. Handle operational transformation (OT) or CRDT for conflict resolution
4. Manage locks and cursors across users

The mock server's message format is compatible with this - you'd just route
messages through WebSocket instead of handling locally.

================================================================================
                          13. API ENDPOINTS
================================================================================

POST /api/open
--------------
Convert Office document to OnlyOffice internal format.

Request:
- Body: Raw file bytes (ArrayBuffer)
- Headers:
  - X-File-Extension: 'docx' | 'xlsx' | 'pptx' | 'doc' | 'xls' | 'ppt' | etc.

Response:
```json
{
    "success": true,
    "data": "DOCY;v5;50544;base64encodeddata...",
    "size": 67406,
    "format": "cryptpad",
    "images": {
        "image1.jpg": "data:image/jpeg;base64,...",
        "image2.png": "data:image/png;base64,..."
    }
}
```

POST /onlyoffice/v8/downloadas/{docId}
--------------------------------------
Convert internal format back to Office format.

Request:
- Body: Document binary in OnlyOffice internal format
- Query params:
  - cmd: JSON with conversion options
    - outputformat: Format code (65=DOCX, 257=XLSX, 129=PPTX, 513=PDF)
    - title: Output filename

Response:
```json
{
    "error": 0,
    "key": "doc_123",
    "url": "/downloads/abc123/Document.docx",
    "end": true
}
```

GET /api/fetch-image
--------------------
Proxy for fetching external images (CORS bypass).

Request:
- Query params:
  - url: The external image URL to fetch

Response:
```json
{
    "success": true,
    "dataUrl": "data:image/jpeg;base64,...",
    "size": 45678
}
```

GET /api/latest-download
------------------------
Poll for completed download (used by client to get download result).

Response:
```json
{
    "ready": true,
    "url": "/downloads/abc123/Document.docx",
    "filename": "Document.docx"
}
```
or
```json
{
    "ready": false
}
```

GET /downloads/{id}/{filename}
------------------------------
Download converted file.

Response: Raw file bytes with appropriate Content-Type

================================================================================
                         15. TROUBLESHOOTING
================================================================================

ISSUE: "File content does not match file extension" error
---------------------------------------------------------
Cause: The document format doesn't match what OnlyOffice expects.
Solution: Ensure x2t conversion outputs the correct format string
(DOCY;v5;... for Word, XLSY;v2;... for Excel, PPTY;v1;... for PowerPoint)

ISSUE: Document loads but shows "Loading document..." forever
-------------------------------------------------------------
Cause: Mock server not connected or getInitialChanges issue.
Solution: 
1. Check that editor.connectMockServer() is called
2. Ensure getInitialChanges() returns [] (empty array)
3. Check browser console for errors

ISSUE: Images not showing in opened documents
---------------------------------------------
Cause: getImageURL() not returning correct URLs.
Solution:
1. Check that images are extracted during conversion
2. Verify currentDocumentImages is populated
3. Ensure getImageURL() returns the correct data URL

ISSUE: Cannot insert images
---------------------------
Cause: APP.AddImage not implemented correctly.
Solution:
1. Ensure window.APP.AddImage is defined before editor loads
2. Check that successCallback is called with { name, url }
3. Verify image is added to documentUrls

ISSUE: Download not working
---------------------------
Cause: Download endpoint or polling issue.
Solution:
1. Check server logs for conversion errors
2. Verify /api/latest-download returns the file
3. Check browser console for fetch errors

ISSUE: Fonts not rendering correctly
------------------------------------
Cause: Font files missing or not loading.
Solution:
1. Ensure public/onlyoffice/v8/fonts/ contains font files
2. Check network tab for 404 errors on font requests
3. Verify font directory structure matches OnlyOffice expectations

ISSUE: Editor iframe not full size
----------------------------------
Cause: CSS issues with iframe sizing.
Solution: Add to your CSS:
```css
#editor { position: relative; width: 100%; height: 100%; }
#editor iframe { 
    position: absolute; 
    width: 100% !important; 
    height: 100% !important; 
}
```

ISSUE: Red "Guest" labels appear / Controls lock when typing
------------------------------------------------------------
Cause: Lock mechanism not properly disabled in single-user mode.
Solution:
1. Ensure connectMockServerFast is used (not connectMockServer)
2. Check that getLock response includes the current user ID
3. Verify APP.onFastChange is set to always return true
4. Check that disableLockMechanism() is being called after iframe loads
5. Ensure GLOBAL_USER_ID is consistent between config and mock server

ISSUE: Changing presentation theme causes error
-----------------------------------------------
Cause: APP.changeTheme function not defined.
Solution: Add to window.APP:
```javascript
window.APP.changeTheme = function(indexTheme) {
    console.log('[changeTheme] Theme change:', indexTheme);
};
```

ISSUE: PDF export not working
-----------------------------
Cause: APP.printPdf not handling the pdf.bin data correctly.
Solution:
1. Check that dataContainer.data exists and has length
2. Verify /api/print-pdf endpoint is working
3. Check server logs for x2t conversion errors
4. Ensure both pdf.bin and document.bin are being sent
